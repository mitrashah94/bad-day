How it works

Connect

Point your agent at Bad Day instead of its real tools. Two minutes. Credentials and client data stay on your machine.

Describe it

Two sentences about what the agent does. Bad Day proposes the rules it should never break. You approve them. No test code.

Curveballs

The world misbehaves. Stale records. Lost acknowledgements. Two customers with the same name. Every rule gets checked.

The trace

Every failure shows the exact turn, what the agent saw, what it did, and what the world recorded. Fix it. Run it again.

Questions

Does it touch my client’s real systems?

No. Bad Day records your agent’s real tool responses once, in a read-only pass, then serves them back with curveballs applied. Writes never reach the origin.

What do I need to set up?

An agent that speaks MCP or HTTP, and two sentences about what it does. Nothing else for the first run.

My evals already cover this.

Evals ask the agent more questions. Bad Day changes the answers the world gives back.

Does it judge response quality?

Only against what the world actually did. “Said done when the write failed” is a failure. “Could have been friendlier” is not.

What if it finds nothing?

The report lists every rule checked, every curveball run, and anything inconclusive. A clean run tells you what was covered, not that your agent is safe.
